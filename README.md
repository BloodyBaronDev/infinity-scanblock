Скачивает публичные списки подсетей интернет-сканеров и государственных организаций, складывает их в `ipset` и отбрасывает **новые входящие** соединения от этих адресов первым правилом `INPUT`.

> [!TIP]
> Сканеры (Shodan, Censys, FOFA, Quake и др.) и проверяющие сети находят серверы по открытым портам и сертификатам. Блокировка на входе уменьшает шум в логах и не даёт им построить базу ваших хостов.

### ✨ Возможности

- ⚡ **Атомарное обновление** через `ipset swap`: ни секунды без защиты
- 🔁 **Автообновление** по таймеру systemd, догоняет пропущенные запуски
- 🚀 **Старт до Docker** после перезагрузки, без ожидания сети
- 🎯 **Точные исключения** `ALLOW` даже внутри заблокированных подсетей
- 🎭 **Открытые порты** `OPEN_TCP`/`OPEN_UDP` для сервисов, которые должны выглядеть обычно
- 🧯 **Защита от битых списков**: набор не трогается, если источник упал или подсетей мало
- 📜 **Журнал блокировок** с лимитом, чтобы не забить диск

## 🔍 Как это работает

1. `scanblock` скачивает обязательные источники. Если хоть один не скачался, набор не меняется (в журнал пишется ошибка).
2. Скачивает дополнительные источники. Недоступный пропускается с записью в журнал.
3. Из всего текста выбирает IPv4 и CIDR, отбрасывает подсети шире `/16`, убирает дубли.
4. Если подсетей меньше `MIN_LINES` (500), набор не обновляется: защита от пустого или испорченного списка.
5. Собирает новый набор `scanblock-new`, добавляет адреса из `ALLOW` как `nomatch`, атомарно меняет его местами с рабочим `scanblock` (`ipset swap`).
6. Сохраняет снимок в `/var/lib/scanblock/rules`.
7. Если их ещё нет, ставит первыми в `INPUT` два правила: `LOG` (с лимитом 30/мин, пачка 50, префикс `SCANBLOCK `) и следом переход в цепочку `SCANBLOCK`. В цепочке порты из `OPEN_TCP`/`OPEN_UDP` возвращаются в `INPUT` (дальше решает ваш обычный файрвол), всё остальное `DROP`. Оба правила действуют только на `conntrack --ctstate NEW`, поэтому уже установленные соединения и ваш исходящий трафик не затрагиваются.

При загрузке `scanblock-restore.service` восстанавливает набор из снимка и ставит те же правила **до старта Docker**, не дожидаясь сети.

> [!NOTE]
> Скрипт ничего из списков не хранит в репозитории: данные скачиваются на вашем сервере при запуске. Условия использования и лицензии списков определяют их авторы; проверяйте их сами. Состав и точность списков не гарантируются, возможны ложные срабатывания.

Свои источники добавляются в `EXTRA_SOURCES` (см. конфиг).

## 📦 Установка

**Требования:** Linux, root, `bash`, `curl`, `ipset`, `iptables`, `systemd`.

```bash
git clone https://github.com/BloodyBaronDev/infinity-scanblock.git scanblock && cd scanblock
sudo ./install.sh
sudoedit /etc/scanblock.conf      # впишите свои адреса в ALLOW
sudo systemctl start scanblock.service
tail /var/log/scanblock.log
```

> [!WARNING]
> **Сначала ALLOW, потом запуск.** Если ваш домашний или офисный адрес окажется в списках, вы потеряете SSH. Держите вторую сессию или консоль провайдера.

Установщик кладёт скрипты в `/usr/local/sbin`, юниты в `/etc/systemd/system`, создаёт `/etc/scanblock.conf` (если его нет), включает таймер (ежедневно около 04:30 + случайная задержка до 15 мин, догоняет пропущенное) и restore-сервис.

## ⚙️ Настройка (`/etc/scanblock.conf`)

Файл читается как bash. Пример: [examples/scanblock.conf](examples/scanblock.conf).

```bash
ALLOW=(
  203.0.113.10        # администратор
  198.51.100.0/24     # офис
)
#MIN_LINES=500
#LOG_LIMIT="30/minute"
#LOG_BURST=50
#EXTRA_SOURCES=(https://example.com/my-list.txt)
#OPEN_TCP="443"
#OPEN_UDP="443"
```

### 🎯 Как работает ALLOW

Каждый элемент добавляется в набор как запись `nomatch`. В `hash:net` совпадение выбирается по самой длинной подсети, поэтому исключение работает в любом случае: и для адреса, и для подсети, и когда адрес лежит **внутри** заблокированной сети (например, ваш `203.0.113.10` в заблокированной `203.0.113.0/24`). Простое удаление строки из списка так не умеет: оно убирает только точное совпадение.

Адрес без маски считается `/32`. Только IPv4. После правки конфига запустите `systemctl start scanblock.service`.

### 🎭 Открытые порты (`OPEN_TCP`, `OPEN_UDP`)

Порты, на которых адреса из списков **не** блокируются: формат `multiport`, через запятую, диапазон через двоеточие (`"443,8443,20000:40000"`). По умолчанию пусто, то есть блокируется всё, как в прежних версиях.

Зачем это нужно. Если порт открыт всему интернету (сайт, TLS-маскировка вроде Reality или masquerade у Hysteria), его смысл в том, чтобы любой, кто постучится, увидел обычный сервис. Когда сервер отвечает на 443 всем, кроме сканеров и госсетей, для них это выглядит как тишина там, где у обычного сайта был бы ответ. Это отличительный признак: проверка, пришедшая из такой сети, не видит маскировку и узнаёт, что сервер прячется именно от неё. Обычные веб-серверы так не делают.

Поэтому:
- в `OPEN_*` ставят только порты, открытые всем и так, и где сервер должен выглядеть обычно;
- SSH, панели и служебные порты туда **не** ставят: закрыть их от сканеров нормально, так поступает почти любой сервер с fail2ban;
- порт, открытый только конкретным адресам, указывать незачем: сканеры до него не дойдут и без scanblock;
- блокировка остаётся заранее по подсетям, а не по поведению, и через `DROP`, а не `REJECT`. Иначе появляется ещё один признак: «ответил, а через минуту замолчал» или RST вместо тишины.

После правки запустите `systemctl start scanblock.service`: цепочка пересоберётся.

## 📊 Журнал и проверка

```bash
tail -n 20 /var/log/scanblock.log                 # результаты обновлений
journalctl -k | grep SCANBLOCK                    # заблокированные соединения (IP, порт, протокол)
ipset list scanblock -terse                       # размер набора
ipset test scanblock 198.51.100.7                 # попадёт ли адрес под блокировку
iptables -L INPUT -n -v --line-numbers | head     # счётчики LOG и DROP, первые два правила
systemctl list-timers scanblock.timer
```

Запись в журнале ядра ограничена лимитом, чтобы блокировки не заполнили диск; счётчик пакетов у DROP показывает реальное число.

## 🩺 Диагностика

- **Потерян SSH**: зайдите через консоль провайдера, добавьте адрес в `ALLOW`, `systemctl start scanblock.service`. Срочно: `ipset add scanblock <ваш-ip>/32 nomatch -exist`.
- **В логе «набор не обновляю»**: недоступен обязательный источник или собралось меньше `MIN_LINES` подсетей. Старый набор продолжает работать.
- **Правил нет после перезагрузки**: `systemctl status scanblock-restore.service`, наличие `/var/lib/scanblock/rules` (создаётся первым успешным запуском).
- **Дубли правил**: `iptables -S INPUT | grep scanblock`; безопасно удалить лишние `iptables -D INPUT ...` и перезапустить сервис.
- **Конфликт с другим фаерволом**: правило вставляется первой строкой `INPUT`; `ufw`/`firewalld` при перезагрузке своих правил могут сдвинуть его. Запуск `scanblock.service` возвращает порядок.

## ↩️ Откат и удаление

Временно отключить:

```bash
sudo systemctl disable --now scanblock.timer
sudo iptables -D INPUT -m conntrack --ctstate NEW -m set --match-set scanblock src -j SCANBLOCK
```

Полностью удалить (правила, набор, юниты, скрипты, снимок):

```bash
sudo ./uninstall.sh
```

Конфиг `/etc/scanblock.conf` и журнал `/var/log/scanblock.log` остаются.

## ⚠️ Ограничения

- Только IPv4 (нет `ip6tables` и IPv6-списков).
- Защищает от **новых входящих** соединений; уже установленные не рвёт, исходящий трафик не фильтрует.
- Подсети шире `/16` отбрасываются намеренно: крупные блоки легко задевают обычных пользователей.
- Качество зависит от сторонних списков: они могут устареть, исчезнуть или содержать лишнее (в том числе адреса легитимных пользователей и ваших провайдеров).
- Сканеры, которые приходят с адресов вне списков, не блокируются; это не замена обычному фаерволу и обновлениям.
- Блокировка сетей государственных организаций может быть неприемлема, если вам нужны входящие соединения оттуда.
- Правила хранятся в ядре; без `scanblock-restore.service` они пропадают при перезагрузке.
